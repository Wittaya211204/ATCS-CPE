Q: if-elif-else ทำงานอย่างไร
A: คำสั่ง if ใช้ตรวจสอบเงื่อนไข หากเป็นจริงจะทำงานในบล็อกนั้น หากไม่จริงจะตรวจสอบ elif (else if) ถัดไปตามลำดับ และถ้าไม่มีเงื่อนไขใดเป็นจริงเลยจะทำงานในบล็อก else ตัวอย่างเช่น if score >= 80: แล้วตามด้วย elif score >= 50: และปิดท้ายด้วย else: โครงสร้างนี้ตรวจสอบเงื่อนไขตามลำดับและหยุดที่เงื่อนไขแรกที่เป็นจริง

Q: for loop และ while loop ต่างกันอย่างไร
A: for loop ใช้เมื่อทราบจำนวนรอบหรือต้องการวนซ้ำผ่านสมาชิกของกลุ่มข้อมูล เช่น for item in my_list: ส่วน while loop ใช้เมื่อต้องการวนซ้ำตราบใดที่เงื่อนไขยังเป็นจริง โดยไม่ทราบจำนวนรอบล่วงหน้า เช่น while count < 10: ควรระวังการเขียน while loop โดยไม่มีเงื่อนไขหยุดที่ถูกต้อง เพราะจะทำให้เกิดลูปไม่รู้จบ (infinite loop)

[หมวด: โครงสร้างควบคุมและลูป]
Q: break, continue และ pass ต่างกันอย่างไร
A: break ใช้หยุดการทำงานของลูปทันทีและออกจากลูปนั้น continue ใช้ข้ามรอบปัจจุบันแล้วกลับไปเริ่มรอบถัดไปโดยไม่หยุดลูปทั้งหมด ส่วน pass เป็นคำสั่งที่ไม่ทำอะไรเลย ใช้เป็นตัวยึดตำแหน่ง (placeholder) เมื่อยังไม่ต้องการเขียนโค้ดในบล็อกนั้น เช่น เมื่อวางโครงฟังก์ชันไว้ก่อนแล้วค่อยเติมทีหลัง

Q: การสร้างฟังก์ชันใน Python ทำอย่างไร
A: ใช้คำสั่ง def ตามด้วยชื่อฟังก์ชันและวงเล็บที่อาจมีพารามิเตอร์ เช่น def greet(name): แล้วตามด้วยบล็อกคำสั่งที่เว้นวรรคเข้าไป ฟังก์ชันสามารถคืนค่าด้วยคำสั่ง return หากไม่มี return จะคืนค่า None โดยอัตโนมัติ พารามิเตอร์สามารถกำหนดค่าเริ่มต้นได้ เช่น def greet(name="โลก") และสามารถรับจำนวนอาร์กิวเมนต์ไม่จำกัดด้วย *args และ **kwargs

Q: ตัวแปร local และ global ต่างกันอย่างไร
A: ตัวแปร local ถูกสร้างภายในฟังก์ชันและมองเห็นได้เฉพาะภายในฟังก์ชันนั้น เมื่อฟังก์ชันทำงานเสร็จตัวแปรจะถูกลบไป ตัวแปร global ถูกสร้างนอกฟังก์ชันและมองเห็นได้ทั่วทั้งไฟล์ หากต้องการแก้ไขตัวแปร global จากภายในฟังก์ชันต้องประกาศด้วยคำสั่ง global ก่อน มิฉะนั้น Python จะสร้างตัวแปร local ใหม่ที่ชื่อซ้ำกันแทนโดยไม่กระทบตัวแปรเดิม

[หมวด: ฟังก์ชันและขอบเขตตัวแปร]
Q: lambda function คืออะไร ใช้เมื่อใด
A: lambda เป็นฟังก์ชันไม่ระบุชื่อ (anonymous function) ที่เขียนในบรรทัดเดียว เหมาะสำหรับฟังก์ชันสั้น ๆ ที่ใช้ครั้งเดียวหรือใช้เป็นอาร์กิวเมนต์ของฟังก์ชันอื่น เช่น sorted(data, key=lambda x: x[1]) รูปแบบคือ lambda parameters: expression โดยไม่มีคำสั่ง return เพราะค่าที่ประเมินได้จะถูกคืนค่าโดยอัตโนมัติ ไม่เหมาะกับตรรกะที่ซับซ้อนเพราะอ่านยาก

[หมวด: ชนิดข้อมูลแบบกลุ่ม]
Q: list, tuple, dict และ set ต่างกันอย่างไร ใช้เมื่อใด
A: list ([]) เก็บข้อมูลตามลำดับและแก้ไขได้ เหมาะกับข้อมูลที่เปลี่ยนแปลงบ่อย tuple (()) คล้าย list แต่แก้ไขไม่ได้ เหมาะกับข้อมูลที่ต้องการความคงที่ เช่น พิกัด dict ({}) เก็บคู่ key-value เหมาะกับข้อมูลที่ต้องการค้นหาด้วยชื่อ set ({} แบบไม่มีคู่ค่า) เก็บสมาชิกที่ไม่ซ้ำกันและไม่มีลำดับ เหมาะกับการตรวจสอบสมาชิกหรือหาความต่าง/ร่วมระหว่างกลุ่มข้อมูล

[หมวด: ชนิดข้อมูลแบบกลุ่ม]
Q: list comprehension คืออะไร และมีข้อดีอย่างไร
A: list comprehension เป็นวิธีสร้าง list แบบกระชับในบรรทัดเดียวแทนการเขียนลูปหลายบรรทัด รูปแบบคือ [expression for item in iterable if condition] เช่น squares = [x**2 for x in range(10) if x % 2 == 0] ข้อดีคือโค้ดสั้นกระชับและมักทำงานเร็วกว่าลูปแบบปกติเล็กน้อย แต่หากตรรกะซับซ้อนเกินไปควรใช้ลูปปกติเพื่อความอ่านง่าย

[หมวด: ชนิดข้อมูลแบบกลุ่ม]
Q: การเข้าถึงสมาชิกด้วย index และ slicing ทำอย่างไร
A: การเข้าถึงสมาชิกใช้ index โดยเริ่มนับจาก 0 เช่น my_list[0] คือสมาชิกตัวแรก และสามารถใช้ index ติดลบเพื่อนับจากท้ายได้ เช่น my_list[-1] คือสมาชิกตัวสุดท้าย การ slicing ใช้รูปแบบ list[start:stop:step] เพื่อดึงข้อมูลเป็นช่วง เช่น my_list[1:4] ดึงตั้งแต่ index 1 ถึงก่อน index 4 และ my_list[::-1] ใช้กลับลำดับสมาชิกทั้งหมด

[หมวด: การจัดการข้อผิดพลาด]
Q: try-except ใช้จัดการข้อผิดพลาดอย่างไร
A: บล็อก try ใช้ครอบโค้ดที่อาจเกิดข้อผิดพลาด หากเกิดข้อผิดพลาดจะกระโดดไปทำงานในบล็อก except ที่ตรงกับชนิดข้อผิดพลาดนั้นแทนที่จะทำให้โปรแกรมหยุดทำงาน เช่น try: กับ result = 10 / 0 แล้วดักด้วย except ZeroDivisionError: สามารถเพิ่มบล็อก else สำหรับโค้ดที่ทำงานเมื่อไม่เกิดข้อผิดพลาด และ finally สำหรับโค้ดที่ทำงานเสมอไม่ว่าจะเกิดข้อผิดพลาดหรือไม่

[หมวด: การจัดการข้อผิดพลาด]
Q: ข้อผิดพลาดที่พบบ่อยใน Python มีอะไรบ้าง
A: ที่พบบ่อยได้แก่ SyntaxError (โครงสร้างโค้ดผิดไวยากรณ์) NameError (เรียกใช้ตัวแปรที่ยังไม่ถูกกำหนด) TypeError (ดำเนินการกับชนิดข้อมูลที่ไม่เข้ากัน เช่น บวกสตริงกับตัวเลข) IndexError (เรียก index ที่เกินขอบเขตของ list) KeyError (เรียก key ที่ไม่มีใน dict) และ ValueError (ค่าที่ส่งเข้าฟังก์ชันมีชนิดถูกต้องแต่ค่าไม่เหมาะสม เช่น int("abc"))

[หมวด: การจัดการข้อผิดพลาด]
Q: ควรใช้ except Exception: แบบกว้าง ๆ หรือไม่
A: โดยทั่วไปไม่แนะนำให้ดักจับ Exception แบบกว้างเกินไปโดยไม่ระบุชนิด เพราะจะซ่อนข้อผิดพลาดที่ไม่คาดคิดและทำให้แก้บั๊กยากขึ้น ควรระบุชนิดข้อผิดพลาดที่คาดว่าจะเกิดให้เฉพาะเจาะจงที่สุด เช่น except FileNotFoundError: หากจำเป็นต้องดักแบบกว้างเพื่อป้องกันโปรแกรมล่ม ควรบันทึก log ของข้อผิดพลาดไว้ด้วยเพื่อตรวจสอบภายหลัง

[หมวด: การเขียนโปรแกรมเชิงวัตถุ (OOP)]
Q: class และ object ใน Python คืออะไร
A: class คือแม่แบบหรือพิมพ์เขียวสำหรับสร้างวัตถุ (object) โดยกำหนดคุณสมบัติ (attributes) และพฤติกรรม (methods) ที่วัตถุนั้นจะมี ส่วน object คือตัวอย่างจริง (instance) ที่สร้างขึ้นจาก class นั้น เช่น class Dog: กำหนดว่าสุนัขมีชื่อและพฤติกรรมเห่าได้ แล้วสร้าง my_dog = Dog("Toffee") เพื่อได้วัตถุสุนัขตัวจริงที่ใช้งานได้

[หมวด: การเขียนโปรแกรมเชิงวัตถุ (OOP)]
Q: __init__ และ self มีหน้าที่อะไร
A: __init__ เป็นเมธอดพิเศษที่ทำงานอัตโนมัติทันทีที่สร้างวัตถุใหม่จาก class ใช้สำหรับกำหนดค่าเริ่มต้นให้กับ attribute ของวัตถุนั้น ส่วน self เป็นพารามิเตอร์ตัวแรกของเมธอดในคลาสที่อ้างอิงถึงตัววัตถุนั้นเอง ทำให้สามารถเข้าถึงและแก้ไข attribute ของวัตถุได้จากภายในเมธอด เช่น self.name = name ต้องใส่ self เป็นพารามิเตอร์แรกเสมอในการนิยามเมธอดของคลาส

[หมวด: การเขียนโปรแกรมเชิงวัตถุ (OOP)]
Q: การสืบทอด (inheritance) ใน Python ทำงานอย่างไร
A: การสืบทอดช่วยให้คลาสลูก (child class) รับคุณสมบัติและเมธอดจากคลาสแม่ (parent class) มาใช้ต่อได้โดยไม่ต้องเขียนซ้ำ กำหนดโดยใส่ชื่อคลาสแม่ในวงเล็บ เช่น class Puppy(Dog): คลาสลูกสามารถเพิ่มเมธอดใหม่หรือเขียนทับ (override) เมธอดเดิมของคลาสแม่ได้ และสามารถเรียกใช้เมธอดของคลาสแม่ผ่าน super() เพื่อขยายพฤติกรรมเดิมแทนที่จะเขียนใหม่ทั้งหมด

[หมวด: การจัดการไฟล์และไลบรารี]
Q: การเปิดและอ่านไฟล์ใน Python ทำอย่างไร
A: ใช้ฟังก์ชัน open() ร่วมกับคำสั่ง with เพื่อให้ไฟล์ถูกปิดอัตโนมัติแม้เกิดข้อผิดพลาด เช่น with open("data.txt", "r", encoding="utf-8") as f: แล้วตามด้วย content = f.read() โหมดที่ใช้บ่อยคือ "r" สำหรับอ่าน "w" สำหรับเขียนทับ "a" สำหรับเพิ่มต่อท้าย และ "rb"/"wb" สำหรับไฟล์แบบไบนารี ควรระบุ encoding="utf-8" เสมอเมื่อทำงานกับข้อความภาษาไทยเพื่อป้องกันปัญหาตัวอักษรผิดเพี้ยน

Q: การ import โมดูลและแพ็กเกจทำอย่างไร
A: ใช้คำสั่ง import ตามด้วยชื่อโมดูล เช่น import math เพื่อใช้ฟังก์ชันด้วย math.sqrt() หรือใช้ from math import sqrt เพื่อเรียกใช้ sqrt() ได้โดยตรง สามารถตั้งชื่อย่อด้วย as เช่น import pandas as pd สำหรับติดตั้งไลบรารีภายนอกที่ไม่มีในไลบรารีมาตรฐานต้องใช้ pip install ชื่อไลบรารี ผ่านบรรทัดคำสั่งก่อนจึงจะ import ใช้งานได้

Q: virtual environment คืออะไร ทำไมจึงควรใช้
A: virtual environment คือสภาพแวดล้อม Python แยกต่างหากสำหรับแต่ละโปรเจกต์ ทำให้แต่ละโปรเจกต์มีไลบรารีและเวอร์ชันของตัวเองโดยไม่ปนกับโปรเจกต์อื่นหรือระบบหลักของเครื่อง ป้องกันปัญหาความขัดแย้งของเวอร์ชันไลบรารี สร้างได้ด้วยคำสั่ง python -m venv env_name แล้วเปิดใช้งานด้วย source env_name/bin/activate บน macOS/Linux หรือ env_name\Scripts\activate บน Windows

Q: จะดีบักโค้ด Python ที่ไม่ทำงานตามคาดได้อย่างไร
A: เริ่มจากอ่านข้อความ error แบบเต็มเพื่อดูว่าเกิดที่บรรทัดใดและชนิดใด ใช้ print() แทรกในจุดต่าง ๆ เพื่อตรวจสอบค่าตัวแปรระหว่างการทำงาน หรือใช้เครื่องมือดีบักในตัวอย่าง pdb ผ่านคำสั่ง import pdb; pdb.set_trace() เพื่อหยุดโปรแกรมและตรวจสอบทีละขั้น สภาพแวดล้อมพัฒนาอย่าง VS Code ก็มี debugger ในตัวที่ตั้งจุดพัก (breakpoint) และดูค่าตัวแปรแบบภาพได้สะดวกกว่า

Q: PEP 8 คืออะไร และทำไมจึงควรปฏิบัติตาม
A: PEP 8 คือแนวทางมาตรฐานการเขียนโค้ด Python ที่ชุมชนยอมรับร่วมกัน ครอบคลุมเรื่องการตั้งชื่อตัวแปร การเว้นวรรค ความยาวบรรทัด การจัดเรียง import และการเขียน docstring การปฏิบัติตามช่วยให้โค้ดอ่านง่าย ทีมงานทำงานร่วมกันได้ราบรื่น และลดข้อผิดพลาดจากความสับสน สามารถตรวจสอบโค้ดอัตโนมัติได้ด้วยเครื่องมืออย่าง flake8 หรือ black ซึ่งจะจัดรูปแบบโค้ดให้ตรงมาตรฐานโดยอัตโนมัติ

Q: ควรเขียน docstring และคอมเมนต์อย่างไรให้มีประโยชน์
A: docstring คือข้อความอธิบายที่เขียนไว้ในบรรทัดแรกของฟังก์ชัน คลาส หรือโมดูล ครอบด้วย """ สามชั้น ใช้บอกว่าโค้ดส่วนนั้นทำอะไร รับพารามิเตอร์อะไร และคืนค่าอะไร ส่วนคอมเมนต์ (#) ควรใช้อธิบาย "เหตุผล" ที่เขียนโค้ดแบบนั้นมากกว่าอธิบายว่า "โค้ดทำอะไร" เพราะโค้ดที่ดีมักอ่านแล้วเข้าใจอยู่แล้ว การเขียนคอมเมนต์มากเกินไปหรืออธิบายสิ่งที่ชัดเจนอยู่แล้วอาจทำให้โค้ดรกโดยไม่จำเป็น

Q: การทดสอบโค้ด (unit testing) ใน Python ทำอย่างไร
A: ไลบรารีมาตรฐานสำหรับการทดสอบคือ unittest ส่วนที่ได้รับความนิยมมากกว่าคือ pytest ซึ่งเขียนง่ายกว่า หลักการคือเขียนฟังก์ชันทดสอบที่ตรวจสอบว่าผลลัพธ์ของฟังก์ชันตรงกับค่าที่คาดหวังหรือไม่ เช่น def test_add(): assert add(2, 3) == 5 การทดสอบช่วยให้มั่นใจว่าเมื่อแก้โค้ดในอนาคตแล้วส่วนอื่นยังทำงานถูกต้อง และช่วยจับข้อผิดพลาดได้ตั้งแต่ช่วงพัฒนาก่อนนำไปใช้งานจริง
